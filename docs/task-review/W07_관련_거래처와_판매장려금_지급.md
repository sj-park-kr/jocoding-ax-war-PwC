# W07 관련 거래처와 판매장려금 지급

## 최종 승인자 검토 (2026-11-11)

**최종 86/100 · 3위** — 기획 / 데이터 / 운영 구현 가능성 / 변경·예외 = **18 / 23 / 26 / 19**. 보완 반영 전에는 80점(17 / 23 / 25 / 15)이었다. 배점은 20/25/30/25이며 공식 배점이 아니다. 아래 승인 조건을 설계에 반영했다고 가정한 제안 점수이고 구현 완료 승인은 아니다. [공통 기준과 최종 순위](00_종합_업무선택.md).

지급 합산 게이트는 구현 범위가 명확하다. 그러나 원본 입금계좌 대조를 새 확장으로 삼는 설명과 변경·상계 처리는 수정해야 한다.

- D-011↔D-024(대표자·주소), D-011↔D-037(대표자·마스터 계좌)의 전이 연결로 **입금 이력 없이도 3곳이 묶인다**. 50개 거래처는 3개사 그룹 1개+단독 47개다. DP-00013·14는 추가 근거다.

- 6월 정산 합계 **3,888,097원**, 개별 최대 **1,867,253원**, 전체 6월 40건 미지급, 과거 그룹 15건 영업지원팀 승인 확인. period_ym 정산월과 다음 달 payment_date를 구분한다.

- 그룹 채권 **48,481,080원**, 90일 초과 **29,202,840원** 확인. 상계 정책·권한은 원본에 없어 자동 상계하지 않는다.

- 과거 15건은 **현재 마스터 기준 사후 재검토 대상**이다. 당시 관계 이력 없이 고의적 회피를 단정하지 않는다.

- 계좌·주소 정정 시 과거 근거·유효시점·기존 승인·예정 지급을 재심사한다. 그룹 분리만으로 자동 전결 복귀하지 않는다.

- **승인 조건:** 소명·변경 이력과 승인 재검토를 실제 확장으로 구현. AI는 소명 증빙 해석·부족 근거 확인에 사용한다. 근거: 마스터·입금 이력·장려금·AR·사전 §4·승인 정책.

### 보완 반영 재평가 (2026-11-11)

- **회복한 감점 (+6):** 필수 확장을 소명·변경 이력으로 교체하고 채권팀의 연체 제약을 조건부 지급 대안에 반영(기획 +1). 소명 회신 판독이라는 운영 중 AI의 입력·출력 정의(구현 +1). 자동 전결 복귀 제거(예외 +2). 자동 상계 제거(예외 +1). 정정 시 재심사와 소명 미회신·반려의 모의 처리(예외 +1).

- **보완해도 남는 감점:** 마스터 변경 이력·소명·수취계좌가 전부 합성이다. 관련자 그룹은 1개뿐이고 상계 정책은 원본에 없다.

- W03과는 가중치에 따라 순서가 바뀌므로 동률로 본다.

## 1. 데이터에서 확인한 사실

### 관련자 식별 키
- `m_agency_cv`(50행): `representative_name`, `business_reg_no`, `address`, `bank_account_no`, `rebate_eligible`, `registered_date`.

- 사업자번호 중복 0건 → 이 키로는 안 묶임.

- 판정 규칙이 `data_dictionary.md` §4에 이미 적혀 있음: "대표자·주소·정산계좌 중 2개 이상 일치 + 전이 연결 + `fin_collection_history_cv.bank_account_no`도 대조".

### 관련자 그룹 (박상현 그룹)
- D-011 ↔ D-024: 대표자 박상현 + 주소 성남시 상공로 128 → 2개 일치

- **함정(동명이인)**: D-034 ↔ D-041은 대표자 박준호만 같고 나머지 불일치 → 묶으면 오탐(미끼).

### 전결 회피 패턴 (`sales_rebate_payment_cv`, 240행 = 40곳 × 2026-01~06)
- 거래처별 월 장려금 최대 1,867,253원 → 200만원 초과 건 0.

## 2. 솔루션안

### A안 (최선): 지급 전 관련자 합산 게이트와 소명 워크플로
- **사용자·결정**: 영업지원팀 정산담당이 6월 배치를 지급/보류/영업임원 상신 결정
- **흐름**:
  1. 미지급 배치 로드
  2. 마스터 + 입금계좌로 그룹화, 일치 키를 근거로 기록
  3. 그룹 월 합계 vs 한도 200만원 → 박상현 그룹 3,888,097원 → 영업임원 승인 대상 자동 분류
  4. 소명요청 발송, 상태 `보류(소명대기)`
  5. 영업임원 승인 → `승인`, 회계에 지급지시
  6. 1~5월 15건은 사후 재검토로 내부감사에 이관
- **AI 역할**: 일치 근거 설명(1개만 일치하면 "관찰"로만) / 소명 회신을 정당사유 유형으로 분류·부족 증빙 지적(가족경영, 건물 공유, 대리입금 위임 등) / 요청문·상신문 초안. **그룹 판정 자체는 결정론 규칙**, AI가 정하지 않음.

- **조건 변경**: D-024가 계좌 변경 신청·주소 정정 → 그룹 재계산. 그룹에서 빠져도 과거 근거·유효시점·기존 승인 재심사 후 전결 경로를 정하고 "변경 직후 분리"를 고위험 표시.

- **정보부족·거절**: 소명 기한(예: 10영업일) 미회신 → 보류 유지·재요청 / 영업임원 반려 → 반려 사유와 함께 지급 취소, 다음 달 지급분에 보류 플래그 승계
- **난이도**: 하~중

### B안: 마스터 변경 통제와 상시 모니터링
- 거래처 등록·변경 요청마다 전체 마스터와 재대조, 영향받는 승인완료·지급예정 건을 재심사 대기열로. 원본에 변경 이력 없어 이벤트 합성 필요, 근거 약함. 난이도 중.

### C안: 장려금과 연체채권 상계 연계
- 90일 초과 연체 그룹은 상계 가능 여부·권한을 별도 확인한 후 승인된 경우에만 상계 시뮬레이션. 재무/채권팀(DSO·회수 목표)과 영업(대리점 관계) 충돌 지점. A안 확장으로 붙이는 게 좋음.

### 권장 조합
- **필수 확장**: 소명·변경 이력에 따른 승인 재검토. 입금계좌 대조는 원본 요구사항이며 마스터 전이만으로도 세 곳이 묶이므로 신규 그룹 형성 효과를 주장하지 않는다.

- **다른 부서 영향**: C안의 채권 상계를 지급액·상태에 실제 반영.

## 3. 함정·리스크
- 정답이 `data_dictionary`와 정책 문서에 그대로 적혀 있음 → 많은 참가자가 같은 그룹을 찾음. 차별화는 탐지가 아니라 승인 → 상태변경 → 사후 재검토 → 정정 처리에서.

- "부정 확정"·"일괄 지급중단" 결론 → 감점 위험(W07.html [범위]). 상태는 `소명대기`처럼 중립적으로.

- 규칙이 결정론적이라 "AI가 판단에 쓰이는 지점"을 소명 판독·위험 분류로 분명히 해야 함. 아니면 단순 룰엔진 평가.

- 데이터가 작음(그룹 1개) → 동명이인 오탐 방지와 변경 이벤트로 깊이를 보여줘야.

## 4. 출제사(삼일PwC) 관점
- **유리**: 전결 회피, 관계사 합산, 직무분리, 감사증적(누가·언제·어떤 근거로)을 심사위원이 바로 알아봄. 승인 이력·사후 재검토·증빙 체크리스트는 회계법인 언어 그대로. 출제자 채용매력 14/15, 현실성 9/10(최고).

- **불리**: 심사위원이 전문가라 얕은 매칭·오탐 방치·증적 누락이 바로 드러남. 출제 의도가 노골적이라 "누구나 찾는 답" 함정. 출제자 천장 22/30, 차별화 10/20(낮음) — 개발자 선호로 몰림 예상.
