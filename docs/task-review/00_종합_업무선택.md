# 업무 선택 최종 검토 (W01~W08)

최종 검토일: 2026-11-11 · 가상기업 판단 기준일: 2026-07-01

**우선 추천은 W02, 차선은 W03, 범위를 작게 유지하기 좋은 대안은 W07이다.** 기존 W03 1위 결론을 변경한다. 보완 반영 재평가 후에도 W02가 1위이며 W03과 W07은 동률로 본다. 이는 업무 선택·제안의 타당성 평가이며 대회 예상 점수나 완성된 시스템의 승인 점수가 아니다. 현재 `public/index.html`은 배포 테스트 화면이므로 운영 구현 완료는 승인하지 않는다.

## 1. 최종 승인 기준

기존 전문가·출제자 점수는 서로 다른 척도여서 단순 평균을 최종 점수로 사용하지 않는다. '출제자'는 실제 심사위원이 아니라 기존 리뷰의 페르소나다. 예상 참가자 비중·채용 매력·특정 업무의 고득점 천장은 확인할 근거가 없어 제외했다. 과거 점수는 업무별 문서에 비교용으로 남겼다.

[A01 §7](../../01_참가자_배포용/A01.html)의 네 심사 관점을 아래 공통 척도로 적용했다. **배점은 이번 검토를 위한 자체 기준이며 공식 배점이 아니다.**

| 축 | 배점 | 판단 기준 |
|---|---:|---|
| 기업 운영·기획 | 20 | 결정 주체·범위·다른 부서의 제약이 구체적인가 |
| 데이터 근거 | 25 | 핵심 수치를 재현할 수 있고 정의·단위·시점·공백을 구분했는가 |
| 운영 구현 가능성 | 30 | 제안 범위가 제출 기한 안에 AI 지원→사람 승인→후속 상태 변경까지 이어질 수 있는가 |
| 변경·예외 설계 | 25 | 정보 부족·거절·정정이 권한을 지키면서 재검토와 후속 처리로 연결되는가 |

각 축은 근거와 처리 경로가 구체적이면 상위, 핵심 가정·권한·후속 처리가 비어 있으면 감점했다. 합성자료나 정보 공백 자체를 일괄 감점하지 않는다. 공백의 처리 설계와 검증 부담을 평가한다. **최종 점수는 업무별 승인 조건을 설계에 반영했다고 가정한 제안 점수다.** 구현으로 입증한 점수가 아니며, 보완 전 점수는 비교용으로 남겼다. 1~3점 차이는 검토자의 판단 차이로 뒤집힐 수 있으므로 확정적 우열로 읽지 않는다.

보완 전 감점은 세 유형으로 나눠 회복했다.

- **전액 회복:** 원본 근거가 있어 설계만 고치면 되는 결함. 예: 회수 자동 롤백, 자동 전결 복귀.
- **절반 회복:** 모의 입력·가정으로 처리 경로는 만들 수 있으나 근거가 합성인 결함. 예: 모의 회신, 소명 텍스트.
- **회복 없음:** 판단의 핵심 수치가 원본에 없는 결함. 예: 능력 단위, 후보 원료 규격.

## 3. 공통 승인 의견

1. **A05 우선:** [A05 §1·§5](../../01_참가자_배포용/A05.html)가 구판 계산 정의와 충돌하면 A05를 적용한다. 쿠폰·환불 이중 차감 산식은 동등한 선택지가 아니다. 주문당 원가·물류비, 수수료 기준, 환불 비용 회수 가정은 명시한다.
2. **모범답안 추정 제외:** [A03 §3·§4](../../01_참가자_배포용/A03.html)는 예시가 모범답안이 아니라고 명시한다. 대체 원료 예시 반복이나 공개된 자료 오류 발견 자체를 특별 가점으로 단정하지 않는다.
3. **실제 확장 입증:** 원본에 이미 명시된 전이 연결·입금계좌 대조만을 신규 확장이라고 부르지 않는다. 추가 이력·회신·예외로 판단·상태가 어떻게 달라지는지 보여야 한다.
4. **부서 영향:** 할 일 생성만으로 충분하다고 가정하지 않는다. 다른 부서의 목표·제약 때문에 승인 경로·배분·계획·후속 처리가 달라져야 한다.
5. **정정과 실행 이력:** 회수·통보·지급·투자 이력을 삭제하지 않는다. 재심사, 미실행 작업 취소, 이미 실행한 작업의 후속 조치로 나눈다.
6. **정책과 가정 구분:** 형제 배치 보류, 사용 승인권자, 소명 기한, 채권 상계, CP 면제는 원본 정책인지 추가 설계인지 표시하고 권한을 정의한다.
7. **필수 요건은 점수와 별개로 확인:** [A01 §4·§5](../../01_참가자_배포용/A01.html)와 [A04](../../01_참가자_배포용/A04.html)의 필수 확장, 다른 부서 영향의 실제 반영, 운영 중 AI의 입력·출력, 정상·변경·정보 부족 또는 거절 사례는 하나라도 빠지면 점수와 무관하게 미충족이다. W02는 재무 제약에 따른 승인 경로 변경과 AI가 읽을 통보서·회의록이 원본에 있다. W07·W04·W06은 AI가 읽을 입력이 전부 합성이다.

## 5. 최종 추천과 승인 상태

**W02 우선 검토를 승인한다.** 계약 갱신과 캠페인 기안의 기한·권한이 명확해 좁은 범위로 운영 흐름을 완결하기 좋다. 통보 초안→승인→발송 모의 처리→수령 확인→실패 시 재요청까지 연결해야 한다. 계약 금액과 표본 성과는 전사 손익으로 환산하지 않는다.

W03은 배치 추적이 강점이나 회수 취소·고객 추적을 바로잡아야 한다. W07은 작게 구현하기 좋지만 소명·변경 이력이라는 실제 확장과 운영 중 AI 역할이 필요하다. 두 업무는 가중치에 따라 순서가 바뀌므로 동률로 본다. 최종 점수는 보완을 설계에 반영했다는 가정이며 구현 후 다시 평가한다.

## 6. 검토 범위와 한계

8개 리뷰·종합표, A01·A03·A04·A05, 관련 업무 HTML·정책·계약·핵심 CSV를 대조했다. 보완 반영 재평가에서는 A01·A03·A04·A05 전문과 W02·W03·W07의 BPMN 안내문을 다시 읽었다. 모든 CSV 수치와 부수 주장을 전수 승인한 것은 아니다. PDF 도식집, 나머지 5개 업무의 BPMN 안내문, 외부 규제, 심사위원 선호·경쟁률은 검증하지 않았다. 실제 구현 실행도 아직 검증할 수 없다.

**배포 방식은 미해결이다.** `axhub.yaml`은 정적 배포 설정이라 운영 중 AI 호출과 상태 저장 경로가 정해지지 않았다. 모든 업무의 구현 점수는 이 경로가 확보된다는 전제다.

[검산 스크립트](verify-review.cjs)는 프로젝트 루트에서 `node docs/task-review/verify-review.cjs`로 실행한다. 원본을 읽어 현금·약정 하회 구간과 기안 집행일 대조·A05 비용 가정의 ROAS·성숙 집단 재구매율·품질 추적·구매액·미출하·관련자 전이·LTM EBITDA와 업무별 점수 합계를 확인한다. 실행 결과 **PASS**를 확인했다. 이 스크립트의 확인 범위를 넘어선 해석·정책·실제 구현을 검증했다는 의미는 아니다.

**업무별 최종 검토 의견이 초기 담당자 의견보다 우선한다.** 제출물 최종 승인에는 [A04](../../01_참가자_배포용/A04.html)의 정상·변경·정보 부족/거절 사례, AI 입력·출력, 사람 승인, 후속 상태 변경 증거가 필요하다.
